# Проверка безопасности личных данных

Учебное веб-приложение для проверки своего email по базе известных утечек XposedOrNot. Проект находится на этапе согласования темы и стека.

## Проблема

Пользователю сложно понять, фигурировал ли его email в известных утечках и какие данные могли стать общедоступными. Сведения об инцидентах разбросаны по разным источникам, поэтому их трудно собрать в одном месте.

## Пользовательские сценарии

1. **Проверка своего email.** Пользователь вводит адрес и получает результат проверки по базе XposedOrNot и количество найденных инцидентов. Перед отправкой формы интерфейс сообщает, что адрес передаётся XposedOrNot для проверки.
2. **Просмотр истории утечек по email.** Пользователь открывает список найденных инцидентов и видит название сервиса, дату или год утечки и категории раскрытых данных, если эти сведения есть у XposedOrNot.
3. **Просмотр сводки по домену.** Пользователь вводит домен и видит агрегированное число известных утечек по данным XposedOrNot. Интерфейс показывает сводные показатели без отдельных email-адресов.

При отсутствии совпадений интерфейс сообщает «В базе XposedOrNot совпадений не найдено». При недоступности внешнего сервиса или превышении лимита запросов приложение показывает отдельное сообщение об ошибке.

## Как будет работать приложение

Браузер отправляет запрос в API приложения. Сервер проверяет ввод, обращается к XposedOrNot по HTTPS и возвращает в интерфейс только сведения, необходимые для отображения результата. Для доменных сводок сервер сначала проверяет кэш в PostgreSQL.

В базе и журналах приложения не сохраняются введённые email-адреса. В PostgreSQL хранятся агрегированные доменные сводки с ограниченным сроком кэширования и суточные счётчики успешных запросов, отсутствия совпадений и ошибок.

## База данных

Для совместной разработки используется PostgreSQL в Supabase.
Схема базы хранится в `db/migrations/001_init.sql`. Этот файл
создаёт таблицы для кэша доменных сводок и дневных счётчиков.

Чтобы подключиться к готовой облачной базе, выполни `npm ci`
и добавь выданную командой строку `DATABASE_URL` в локальный
файл `.env` в корне проекта. Файл `.env` не хранится в GitHub.

Модуль `db/queries.mjs` предоставляет три функции:

- `getDomainSummary(domain)` возвращает свежую сводку или `null`.
- `saveDomainSummary(domain, breachCount)` сохраняет или обновляет
  сводку на 24 часа.
- `incrementCheckCount(checkType, outcome)` увеличивает дневной
  счётчик проверок по типу и результату.
  ### Кэш результатов проверки email

PostgreSQL хранит результаты успешных проверок email в течение **12 часов**. Если пользователь повторно проверяет тот же адрес и в кэше есть свежий результат, сервер возвращает его без дополнительного запроса к XposedOrNot. Пустой список утечек тоже кэшируется. Ошибки внешнего сервиса в кэш не записываются.

Таблица `app_private.email_check_cache` создаётся миграцией `db/migrations/002_email_cache.sql`. В ней хранятся ключ, вычисленный из email с помощью HMAC-SHA-256, результат проверки и время истечения записи. Сам адрес в таблице не хранится.

| Функция | Назначение |
| --- | --- |
| `getEmailCheckCache(email)` | Возвращает свежий результат проверки или `null`, если запись отсутствует либо просрочена. |
| `saveEmailCheckCache(email, result)` | Сохраняет результат проверки или обновляет существующую запись, устанавливая новый срок действия в 12 часов. |

Для работы с кэшем задай `EMAIL_CACHE_SECRET` в локальном файле `.env`. Серверы, которые используют общий кэш, должны использовать одинаковый секрет. Значение секрета хранится вне репозитория.

Через 12 часов запись перестаёт использоваться приложением. В общей базе Supabase задача `delete-expired-email-cache` каждые **15 минут** удаляет просроченные строки.

## Запуск и проверка серверной части

Для работы серверной части необходимы **Node.js**, доступ к базе данных Supabase и подключение через **VPN**. VPN требуется для стабильного доступа к API XposedOrNot.

Перед первым запуском необходимо создать локальный файл `.env` в корне проекта и указать в нём параметры подключения к Supabase (`DATABASE_URL`), секрет кэша (`EMAIL_CACHE_SECRET`) и остальные необходимые настройки окружения.

### Установка и запуск

1. Открой терминал в корневой папке проекта.
2. Установи зависимости:

   ```powershell
   npm.cmd ci
   ```

   Команда устанавливает библиотеки, указанные в `package-lock.json`. Повторять её при каждом запуске не требуется.

3. Включи VPN.
4. Запусти сервер:

   ```powershell
   npm.cmd start
   ```

После запуска сервер будет доступен по адресу `http://localhost:3000`. Окно терминала с работающим сервером необходимо оставить открытым.

### Проверка работоспособности

Для проверки открой **второе окно PowerShell**, не закрывая первое.

**1. Проверка состояния сервера:**

```powershell
Invoke-RestMethod -Method Get -Uri http://localhost:3000/api/health
```

Ожидаемый результат:

```json
{
  "status": "ok"
}
```

**2. Проверка email:**

```powershell
Invoke-RestMethod -Method Post `
  -Uri http://localhost:3000/api/email/check `
  -ContentType "application/json" `
  -Body '{"email":"example@gmail.com"}' |
  ConvertTo-Json -Depth 20
```

В ответе отображаются сведения о найденных утечках и поле `cached`, показывающее, был ли результат получен из кэша (`true`) или непосредственно от XposedOrNot (`false`).

**3. Проверка сводки по домену:**

```powershell
Invoke-RestMethod -Method Post `
  -Uri http://localhost:3000/api/domain/summary `
  -ContentType "application/json" `
  -Body '{"domain":"gmail.com"}' |
  ConvertTo-Json -Depth 20
```

В ответе отображается количество известных утечек для указанного домена и признак использования кэша.

Для проверки кэширования можно повторить один и тот же запрос. При наличии действующей записи второй запрос должен вернуть `cached: true`.

Для остановки сервера используется сочетание клавиш `Ctrl + C` в первом окне PowerShell.

## WEB-интерфейс

В рамках проекта был реализован клиентский интерфейс для взаимодействия с API проверки утечек.

**Что сделано:**
- Сверстан адаптивный пользовательский интерфейс (HTML5) с использованием современных семантических тегов и доступности (a11y).
- Написан дизайн (CSS) в стиле Digital/Glassmorphism: реализованы стеклянные карточки с размытием (`backdrop-filter`), фоновая сетка, интерактивные блики, следующий за курсором мыши.
- Реализован переключатель светлой и темной темы с сохранением выбора пользователя в `localStorage` и поддержкой плавных переходов (`View Transitions API`).
- Написана клиентская логика (Vanilla JS):
  - Валидация введенных email-адресов и доменов перед отправкой запросов.
  - Асинхронные запросы (`fetch`) к эндпоинтам сервера (`/api/email/check`, `/api/domain/summary`).
  - Отрисовка состояний загрузки (skeleton-экраны), ошибок и пустых результатов.
  - Вывод карточек утечек с переводом технических категорий данных на русский язык.
  - Классификация украденных данных по уровням критичности (критично / чувствительно / базово) с соответствующим цветовым кодированием и иконками.
  - Реализован индикатор уровня риска, фильтрация утечек по критичности и сортировка по годам.
  - Добавлена функция копирования подробного текстового отчета в буфер обмена.
  - Добавлены "горячие клавиши" (например, `/` для фокуса на поиске) и кнопки быстрой очистки полей.
 
### Особенности реализации и безопасность (Frontend)

- Безопасность (XSS Protection): Все данные, получаемые от внешнего API XposedOrNot, проходят обязательную очистку через кастомную функцию escapeHtml() перед вставкой в DOM. Это предотвращает внедрение вредоносного скрипта, если база утечек вернет некорректные данные.
- Приватность: В соответствии с концепцией проекта, интерфейс явно уведомляет пользователя о том, что его email передается стороннему сервису. Введенные данные не сохраняются в браузере (не используются куки для логирования запросов).
- UX / Удобство использования: 
  - Для полей ввода реализована функция быстрой очистки (крестик внутри инпута) и обработка нажатия клавиши Escape.
  - Реализована поддержка prefers-reduced-motion (анимации отключаются, если у пользователя в системе включен режим экономии энергии).
  - Для форм добавлена нативная HTML-валидация и кастомные сообщения об ошибках под полями ввода.
- Адаптивность: Интерфейс корректно отображается на мобильных устройствах (элементы перестраиваются в колонку, уменьшаются отступы и шрифты).
